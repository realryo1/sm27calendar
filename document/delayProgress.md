# 運行情報（遅延リアルタイム監視）実装メモ・進捗

`tienResearch.md`（調査資料）をもとに作っている運行情報機能の、実際の実装と進捗。
メインページへ組み込む前の試験版として、`website/delay/`（表示）と `worker/`（収集）に分けて作っている。

最終更新：2026-10-25

## 全体の構成

```
[各事業者のサイト] ←5分に1回だけ取得― [Cloudflare Worker（Cron）] → [Workers KV に JSON 1本]
                                                                        ↓
[利用者のブラウザ（website/delay/）] ―1分ごとに取得→ [Worker の /status.json（エッジで60秒キャッシュ）]
```

- 閲覧者が増えても、事業者サイトへのアクセスは Cron の回数（5分に1回）のまま
- ブラウザは事業者サイトへ直接アクセスしない（CORS で読めないうえ、アクセス集中の原因になるため）

| 項目 | 内容 |
| --- | --- |
| 配信 URL | `https://sm27-delay.realryo1.workers.dev/status.json` |
| Cron | `2-59/5 * * * *`（毎時 :02, :07, …） |
| KV | `DELAY_KV`（キー `status`） |
| デプロイ | Cloudflare の GitHub 連携（Workers Builds）。`main` に push すると `worker/` が自動デプロイ |
| ログ | `[observability] enabled = true`。ダッシュボードの Observability で見る |
| 試験ページ | `website/delay/`（GitHub Pages のワークフローを手動実行して公開。`noindex`、メインページからはリンクしていない） |

## 対応している交通機関

| 対象 | 取得元 | 取れる情報 |
| --- | --- | --- |
| JR北海道 | `www3.jrhokkaido.co.jp/webunkou/json/area/area_01.json` | 全エリア・全線区の本日／明日の状態（0：遅れの情報なし／1：遅れや運休あり）。遅れと運休の区別はない |
| 札幌市営地下鉄 | `operationstatus.city.sapporo.jp/unkojoho/top.html` | 3路線の状態と短い定型文（「平常運転しています」など） |
| 新千歳空港（国内線） | `www.hokkaido-airports.com/api/v1/new-chitose/static/fis/domestic/today.json` | 当日の出発・到着全便。備考 ID（RemarkID）で欠航・遅れ・引き返し等を分類 |

### 調査資料との違い（実際に確かめた結果）

- JR北海道：資料の `senku_xx.json` ではなく、`area_01.json` 1本で全線区が取れる
- 地下鉄：交通局トップの本文ではなく、別ドメインの HTML パーツに状態がある
- 空港：HTML の表を読む必要はなく、公式 FIS が使っている JSON がある。備考 ID の分類は公式 FIS の main.js と同じ対応表を使う
- 市電（stsp.or.jp）：調査時点でサイトがメンテナンス中で取得できなかった
- JR北海道と札幌市の配信元は Imperva（ボット対策）の配下だが、Cloudflare からの取得は弾かれていない（2026-10-25 時点）

## JSON（`/status.json`）

```jsonc
{
  "version": 1,
  "updated_at": "2026-10-25T21:12:27+09:00",   // この回の取得時刻
  "next_update_at": "2026-10-25T21:17:27+09:00", // 次の Cron の予定時刻（Worker が入れる）
  "services": {
    "jr":      { "ok": true, "fetched_at": "…", "last_success_at": "…", "source_time": "…", "items": [ /* 線区 */ ] },
    "subway":  { "ok": true, …, "items": [ /* 路線 */ ] },
    "airport": { "ok": true, …, "groups": [ /* 系列ごとの集計 */ ], "flights": [ /* 遅れ・欠航の便 */ ] }
  },
  "meta": { "source_errors": [], "fallback_active": false }
}
```

- 取得に失敗した事業者は、前回成功時のデータを残したまま `ok: false` にし、`meta.source_errors` に記録する（段階的縮退）
- 空港の `flights[].kind`：`cancelled`（欠航）／`delayed`（遅れ）／`diverted`（引き返し等）／`done`（出発・到着済みで30分以上遅れた便）
- 空港の系列の状態：欠航・引き返しが3割以上 → `suspended`、欠航・引き返しか30分以上の遅れが1便でもある → `delay`、それ以外 → `normal`。`done` の便は状態の判定に使わない

## 決めたこと

- **Cron を :02, :07, … にした**：新千歳空港の FIS は毎時 :01, :06, … に更新される。:00, :05, … に取ると、いつも約5分前のデータになっていた
- **次回の更新時刻は Worker が出す**（`next_update_at`）：Cron の設定をページ側に二重に持たないため
- **空港の遅れの判定は30分以上**：5分遅れ1便で系列全体が「遅れ」になるのは過敏だったため
- **出発・到着済みの遅れ便は30分以上だけ**：平常の日でも15分以上の遅れは60便近くある。ページでは初期は隠し、チェックボックスで表示
- **事業者の長文は取り込まない**：状態・便名・時刻などの事実だけを扱う（資料の第6章）
- **企業ロゴは使わない**：公認と誤解されるおそれと、各社の利用規約のため。代わりに会社の色を使う
- **会社の色**
  - JR北海道 `#59bb32`、札幌市交通局 `#005eaa`、北海道エアポート `#0e819f`、地下鉄のラインカラーは各社公式サイトの CSS で確認した値
  - 航空会社の機体色は色見本（PANTONE・DIC）からの参考値と、指定した値。2色の会社は FDA（赤に左端4分の1が黄）・AIRDO（上下で水色と黄）・スカイマーク（紺に黄色の★）
- **試験ページは Service Worker の対象外**（`website/sw.js`）：`/delay/` を開くとカレンダーが返る問題があったため。運行情報は古いものを出すと危険なので、オフライン用のキャッシュもしない
