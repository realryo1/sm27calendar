# 運行情報（遅延リアルタイム監視）実装メモ・進捗

`tienResearch.md`（調査資料）をもとに作っている運行情報機能の、実際の実装と進捗。
メインページへ組み込む前の試験版として、`website/delay/`（表示）と `worker/`（収集）に分けて作っている。

最終更新：2026-10-26

## 全体の構成

```
[各事業者のサイト] ←5分に1回だけ取得― [Cloudflare Worker（Cron）] → [Workers KV に JSON 1本]
                                                                        ↓
[利用者のブラウザ（website/delay/）] ―1分ごとに取得→ [Worker の /status.json（エッジで60秒キャッシュ）]
```

- 閲覧者が増えても、事業者サイトへのアクセスは Cron の回数（5分に1回）のまま
- ブラウザは事業者サイトへ直接アクセスしない（CORS で読めないうえ、アクセス集中の原因になるため）

| 項目 | 内容 |
| --- | --- |
| 配信 URL | `https://sm27-delay.realryo1.workers.dev/status.json` |
| 監視用 URL | `https://sm27-delay.realryo1.workers.dev/health`（異常なら 503） |
| Cron | `2-59/5 * * * *`（毎時 :02, :07, …、通年） |
| KV | `DELAY_KV`（キー `status`） |
| デプロイ | Cloudflare の GitHub 連携（Workers Builds）。`main` に push すると `worker/` が自動デプロイ |
| ログ | `[observability] enabled = true`。ダッシュボードの Observability で見る |
| 試験ページ | `website/delay/`（GitHub Pages のワークフローを手動実行して公開。`noindex`、メインページからはリンクしていない） |

### 調査資料との違い（実際に確かめた結果）

- JR北海道：資料の `senku_xx.json` ではなく、`area_01.json` 1本で全線区が取れる
- 地下鉄：交通局トップの本文ではなく、別ドメインの HTML パーツに状態がある
- 空港：HTML の表を読む必要はなく、公式 FIS が使っている JSON がある。備考 ID の分類は公式 FIS の main.js と同じ対応表を使う
- 市電（stsp.or.jp）：調査時点でサイトがメンテナンス中で取得できなかった
- JR北海道の状態値 `2` は「サービス時間外」（webunkou の `js/common_area_operation.js` で確認）。深夜は全線区が `2` になる。2026-10-26 0時ごろ、構造変更の検知がこれを「1つも読めない」と誤判定して `/health` が 503 になったため、`offhours` として扱うようにした
- JR北海道と札幌市の配信元は Imperva（ボット対策）の配下だが、Cloudflare からの取得は弾かれていない（2026-10-25 時点）
- 高速道路（2026-10-26 調査）
  - JARTIC は使わない：サイトの利用規約（第2条）が、コンテンツを営利・非営利を問わず無断で第三者に閲覧・表示・提供することを禁じている。オープンデータの「交通規制情報」は毎月月初の更新で、リアルタイムの通行止めには使えない
  - NEXCO東日本のドラとら（`www.drivetraffic.jp`）は、調査時（深夜0時ごろ）メンテナンス中だった。当面止まったままの可能性があるので使わない
  - アイハイウェイ（`ihighway.jp`）を使う。NEXCO東日本の道路（北海道を含む）も対象で、規制情報が JSON 1本にまとまっている。「ご利用上の注意」は、コンテンツを許諾なく複製頒布・出版・放送などに二次利用することを禁じている。そのため JR などと同じく、取り込むのは路線・区間・方向・種類・原因の事実だけにし、文章と地図の座標は使わない
  - 北海道開発局の「北海道地区道路情報」は、全国版の「道路情報提供システム」（`www.road-info-prvs.mlit.go.jp`、直轄国道）に移っている

## JSON（`/status.json`）

```jsonc
{
  "version": 1,
  "updated_at": "2026-10-25T21:12:27+09:00",   // この回の取得時刻
  "next_update_at": "2026-10-25T21:17:27+09:00", // 次の Cron の予定時刻（Worker が入れる）
  "services": {
    "jr":      { "ok": true, "fetched_at": "…", "last_success_at": "…", "fail_count": 0, "source_time": "…", "items": [ /* 線区 */ ] },
    "subway":  { "ok": true, …, "items": [ /* 路線 */ ] },
    "airport": { "ok": true, …, "groups": [ /* 系列ごとの集計 */ ], "flights": [ /* 遅れ・欠航の便 */ ] },
    "expressway": { "ok": true, …, "roads": [ /* 路線ごとの状態と規制の区間 */ ] }
  },
  "meta": { "source_errors": [], "source_warnings": [], "fallback_active": false }
}
```

- 取得に失敗した事業者は、前回成功時のデータを残したまま `ok: false` にし、`meta.source_errors` に記録する（段階的縮退）
- `fail_count`：その事業者が連続で失敗した回数。成功したら0に戻る
- `meta.source_warnings`：取得はできたが一部が読めないとき（JR の線区キーや地下鉄の路線名が見つからないなど）。事業者側の構造変更の疑い
- 中身がまったく読めないときは失敗扱いにして前回のデータを残す：JR は線区が1つも読めない、地下鉄は3路線とも見つからない、空港は便が0件
- 空港の `flights[].kind`：`cancelled`（欠航）／`delayed`（遅れ）／`diverted`（引き返し等）／`done`（出発・到着済みで30分以上遅れた便）
- 高速道路の `roads[].items[]`：`kind`（`closed` など）・`label`（通行止 など）・`major`・`section`（区間）・`direction`・`reason`（作業・雪など）・`detail`
- 高速道路の路線の状態：通行止があれば `suspended`、重要な規制（ランプ閉鎖・チェーン規制・冬用タイヤ等装着・片側交互通行・渋滞・事故・故障車・落下物）があれば `delay`、それ以外は `normal`。車線規制・速度規制・除雪作業などは状態に使わず、ページでは件数だけ出す
- 空港の系列の状態：欠航・引き返しが3割以上 → `suspended`、欠航・引き返しか30分以上の遅れが1便でもある → `delay`、それ以外 → `normal`。`done` の便は状態の判定に使わない

## 決めたこと

- **Cron を :02, :07, … にした**：新千歳空港の FIS は毎時 :01, :06, … に更新される。:00, :05, … に取ると、いつも約5分前のデータになっていた
- **次回の更新時刻は Worker が出す**（`next_update_at`）：Cron の設定をページ側に二重に持たないため
- **空港の遅れの判定は30分以上**：5分遅れ1便で系列全体が「遅れ」になるのは過敏だったため
- **出発・到着済みの遅れ便は30分以上だけ**：平常の日でも15分以上の遅れは60便近くある。ページでは初期は隠し、チェックボックスで表示
- **事業者の長文は取り込まない**：状態・便名・時刻などの事実だけを扱う（資料の第6章）
- **企業ロゴは使わない**：公認と誤解されるおそれと、各社の利用規約のため。代わりに会社の色を使う
- **高速道路は道央道（苫小牧〜新千歳空港〜札幌JCT）と札樽道だけ**：道央道は函館〜士別剣淵と長いので、区間名に苫小牧・千歳・恵庭・島松・北広島・輪厚・札幌南・大谷地・札幌JCT を含むものだけを載せる
- **高速道路のカードには「出発前に必ず公式を確認」を出す**：表示まで10〜15分遅れるうえ、このページだけを頼りにされるのがいちばんのリスクのため
- **会社の色**
  - JR北海道 `#59bb32`、札幌市交通局 `#005eaa`、北海道エアポート `#0e819f`、地下鉄のラインカラーは各社公式サイトの CSS で確認した値
  - 航空会社の機体色は色見本（PANTONE・DIC）からの参考値と、指定した値。2色の会社は FDA（赤に左端4分の1が黄）・AIRDO（上下で水色と黄）・スカイマーク（紺に黄色の★）
- **Cron は通年5分ごと**：期間で間隔を変えると `next_update_at` の計算や設定が複雑になるため、単純さを優先した（KV 書き込みは1日288回で無料枠内）
- **異常は `/health` を Worker の外から定期的に見て知る**：Worker 自体や Cron が止まったときにも気づけるようにするため。見るのは Grok Bot の Routine（構成を増やさないため、専用の監視サービスは使わない）。秘密情報（Webhook URL など）も持たなくて済む
  - 503 にする条件：`updated_at` が17分以上古い（Cron が3回動いていない）／同じ事業者で3回続けて失敗／`source_warnings` がある
  - 1回だけの失敗は一時的なことが多いので、200 のまま `notes` に載せる
- **配信のキャッシュは短いまま**（`max-age=60, stale-while-revalidate=300`）：資料の案（`swr=86400`）だと古い運行情報が出続けるおそれがある。Worker や KV が止まっても、ページは前に表示した内容を残し、`updated_at` が古ければ「更新が止まっています」と出すので、長いキャッシュは使わない
- **Worker に一度もつながらないとき**は、ページに JR・地下鉄・空港の公式リンクを出す（名前と URL は `collect.js` の `SOURCES` と `delay.js` の `OFFICIAL` で合わせる）
- **試験ページは Service Worker の対象外**（`website/sw.js`）：`/delay/` を開くとカレンダーが返る問題があったため。運行情報は古いものを出すと危険なので、オフライン用のキャッシュもしない
