# 運行情報（遅延リアルタイム監視）実装メモ・進捗

`tienResearch.md`（調査資料）をもとに作っている運行情報機能の、実際の実装と進捗。
メインページへ組み込む前の試験版として、`website/delay/`（表示）と `worker/`（収集）に分けて作っている。

最終更新：2026-10-26

## 全体の構成

```
[各事業者のサイト] ←5分に1回だけ取得― [Cloudflare Worker（Cron）] → [Workers KV に JSON 1本]
                                                                        ↓
[利用者のブラウザ（website/delay/）] ―1分ごとに取得→ [Worker の /status.json（isolate のメモリに60秒）]
```

- 閲覧者が増えても、事業者サイトへのアクセスは Cron の回数（5分に1回）のまま
- ブラウザは事業者サイトへ直接アクセスしない（CORS で読めないうえ、アクセス集中の原因になるため）

| 項目 | 内容 |
| --- | --- |
| 配信 URL | `https://delay.realryo1.com/status.json` |
| 監視用 URL | `https://delay.realryo1.com/health`（異常なら 503） |
| Cron | `2-59/5 * * * *`（毎時 :02, :07, …、通年） |
| KV | `DELAY_KV`（キー `status`） |
| デプロイ | Cloudflare の GitHub 連携（Workers Builds）。`main` に push すると `worker/` が自動デプロイ |
| ログ | `[observability] enabled = true`。ダッシュボードの Observability で見る |
| 試験ページ | `website/delay/`（GitHub Pages のワークフローを手動実行して公開。`noindex`、メインページからはリンクしていない） |

### 調査資料との違い（実際に確かめた結果）

- JR北海道：資料の `senku_xx.json` ではなく、`area_01.json` 1本で全線区が取れる
- 地下鉄：交通局トップの本文ではなく、別ドメインの HTML パーツに状態がある
- 空港：HTML の表を読む必要はなく、公式 FIS が使っている JSON がある。備考 ID の分類は公式 FIS の main.js と同じ対応表を使う
- 市電（stsp.or.jp）：調査時点でサイトがメンテナンス中で取得できなかった
- JR北海道の状態値 `2` は「サービス時間外」（webunkou の `js/common_area_operation.js` で確認）。深夜は全線区が `2` になる。2026-10-26 0時ごろ、構造変更の検知がこれを「1つも読めない」と誤判定して `/health` が 503 になったため、`offhours` として扱うようにした
- JR北海道と札幌市の配信元は Imperva（ボット対策）の配下だが、Cloudflare からの取得は弾かれていない（2026-10-25 時点）
- 高速道路（2026-10-26 調査）
  - JARTIC は使わない：サイトの利用規約（第2条）が、コンテンツを営利・非営利を問わず無断で第三者に閲覧・表示・提供することを禁じている。オープンデータの「交通規制情報」は毎月月初の更新で、リアルタイムの通行止めには使えない
  - NEXCO東日本のドラとら（`www.drivetraffic.jp`）は、調査時（深夜0時ごろ）メンテナンス中だった。当面止まったままの可能性があるので使わない
  - アイハイウェイ（`ihighway.jp`）を使う。NEXCO東日本の道路（北海道を含む）も対象で、規制情報が JSON 1本にまとまっている。「ご利用上の注意」は、コンテンツを許諾なく複製頒布・出版・放送などに二次利用することを禁じている。そのため JR などと同じく、取り込むのは路線・区間・方向・種類・原因の事実だけにし、文章と地図の座標は使わない
  - 北海道開発局の「北海道地区道路情報」は、全国版の「道路情報提供システム」（`www.road-info-prvs.mlit.go.jp`、直轄国道）に移っている
- バス2社（2026-10-26 調査）
  - 両社とも利用規約のページはなく、プライバシーポリシーと著作権表示だけ。robots.txt でも対象のページは禁止されていない。ほかと同じく、状態と系統名・区間の事実だけを扱う
  - 中央バス：運休情報の RSS を使う。機械で読む前提で公開されているもので、HTML を読むより形が安定している。調査時は運休がなく空だったので、項目の形式は 2026年1〜2月の Wayback Machine の保存（全路線・系統ごと・区分ごとのフィード）で確認した
    - `topic=stop_list`（全路線）1本に、空港連絡バスも高速おたる号も入る。項目の題名は「方向/英語 路線名（便）  状態 理由の文章」、`guid` は `系統番号_ket_方向_…`。空港連絡バスは題名に「空港連絡バス」、高速おたる号は「高速おたる号」、高速とまこまい号は「高速とまこまい号」が入るので、それで分ける（高速とまこまい号は、苫小牧西港へ行く便があるので 2026-10-26 に足した。「もし飛行機が止まったら？」のバスの行にも運休の有無を出す）（空港連絡バスは 2026-12-11 に系統が変わるので、系統番号は固定しない）
    - 題名の後ろの理由の文章（「高速道路通行止めのため…」）は取り込まない。状態の語より前（方向・系統名・時刻）だけを使う
    - **存在しない topic を指定しても、題名が「運休情報」の空のフィードが 200 で返る**（`stop_kind2` で確認）。運休なしと見分けられないので、チャンネルの題名が「北海道中央バス運休情報」であることを確かめ、違えば失敗扱いにする
    - 区分ごとのフィード（`stop_kind3` が空港連絡バス）もあるが、高速おたる号の区分のフィードはないので、全路線の1本にした
    - 初めは運休情報のトップ（HTML）の「運休有」の画像で系統ごとの有無を見ていたが、RSS のほうが方向・便・状態の違い（運休中／一部便運休中）まで分かるので切り替えた
  - 北都交通：資料のとおり、トップに系統ごとの状態がある。アイコンの番号（`ico-status01〜03`）と文言（平常運行／一部区間運休／全便運休）の対応は、2025〜2026年冬の Wayback Machine の保存で確認した。桑園線・定山渓線は調査時も冬の保存でも「全便運休」のまま（運行していない時期と思われる）
  - 「中央バスナビ」（navitime）のリアルタイム運行情報は、接近情報の地図で、運休の一覧ではないので使わない
- フェリー3社（2026-10-26 調査）
  - 3社とも利用規約のページは見当たらない。robots.txt はシルバーフェリーとさんふらわあにはなく、新日本海フェリーは管理用のパスだけ禁止。トップページを5分に1回取るだけにする
  - 荒天時の表示は、2025〜2026年冬の Wayback Machine の保存で確かめた（シルバーフェリー12件・さんふらわあ12件・新日本海フェリー13件）
  - シルバーフェリー：資料のとおりトップに欄がある。クラスは `normal` と `delay` の2種類で、`delay` のときは「欠航または遅延便があります」とお知らせへのリンクになる
    - 便ごと（船ごと）の状況は、そのお知らせの本文にだけある。手書きだが、2024〜2026年の保存（低気圧・津波警報）では「【3月16日（日）】」「＜八戸発＞／＜苫小牧発＞」「08:45発便 シルバープリンセス 欠 航」の形でそろっている。日付・出発港・時刻・船名だけを取り込み、状態の文言は「欠航」「運休」「遅延・遅れ」「出港済」「運航予定・定刻」の語から、こちらのラベル（欠航／運休／出港済／運航予定／遅れ見込み／お知らせを確認）に分類する
    - 平常時は便ごとの情報がない。定期検査の運休や代船（ブルーマーメイド）の期間もトップは「通常運航しています」のままなので、平常時に船ごとに「通常運航」と並べることはしない
    - お知らせを取りに行くのは、トップが `delay` で、リンクが自社サイト（`www.silverferry.jp`）のときだけ。取れなかったり形が違ったりしても、トップの状態は出す（`sailings` が null か空）
  - さんふらわあ：「運航状況」欄は自由記述で、グッズの品切れや電話番号の案内まで入っている。文章は取り込まず、冒頭が「本日は通常（とおり）運航しております」なら通常運航、それ以外は「欠航」「遅」の語の有無で状態だけを判定する。荒天時は冒頭が「【…運航状況について】 2026.2.28 09：00現在」の形になるので、この時刻を `source_time` にする
  - 新日本海フェリー：資料の「snfinfo_xxxx」は個々のお知らせのページの URL（`/snfinfo0206/` など）。トップのヘッダーに、運航に影響があるときだけ「運航状況」のお知らせが並ぶ（平常時は空）。題名（「冬型気圧配置の影響による運航状況（2/7 10:00現在）」など）は事業者の文章なので取り込まない。「運航船舶変更について」「船舶の整備点検による運航状況」のような欠航でないお知らせも2週間ほど出続けることがある

## JSON（`/status.json`）

```jsonc
{
  "version": 1,
  "updated_at": "2026-10-25T21:12:27+09:00",   // この回の取得時刻
  "next_update_at": "2026-10-25T21:17:27+09:00", // 次の Cron の予定時刻（Worker が入れる）
  "services": {
    "jr":      { "ok": true, "fetched_at": "…", "last_success_at": "…", "fail_count": 0, "source_time": "…", "items": [ /* 線区 */ ] },
    "subway":  { "ok": true, …, "items": [ /* 路線 */ ] },
    "airport": { "ok": true, …, "groups": [ /* 系列ごとの集計 */ ], "flights": [ /* 遅れ・欠航の便 */ ] },
    "expressway": { "ok": true, …, "roads": [ /* 路線ごとの状態と規制の区間 */ ] },
    "chuobus": { "ok": true, …, "groups": [ /* 空港連絡バス・高速おたる号。運休のある系統・便 */ ] },
    "hokto":   { "ok": true, …, "items": [ /* 空港連絡バスの系統ごとの状態 */ ] },
    "silverferry": { "ok": true, …, "status": "normal", "message": "通常運航しています", "notice_url": null, "sailings": null },
    "sunflower":   { "ok": true, …, "status": "normal", "label": "通常運航" },
    "snf":         { "ok": true, …, "status": "normal", "list_url": "…", "notices": [ /* { date, url } */ ] }
  },
  "meta": { "source_errors": [], "source_warnings": [], "fallback_active": false }
}
```

- 取得に失敗した事業者は、前回成功時のデータを残したまま `ok: false` にし、`meta.source_errors` に記録する（段階的縮退）
- `fail_count`：その事業者が連続で失敗した回数。成功したら0に戻る
- `meta.source_warnings`：取得はできたが一部が読めないとき（JR の線区キーや地下鉄の路線名が見つからないなど）。事業者側の構造変更の疑い
- 中身がまったく読めないときは失敗扱いにして前回のデータを残す：JR は線区が1つも読めない、地下鉄は3路線とも見つからない、空港は便が0件、中央バスは RSS の形でない・チャンネルの題名が違う、北都交通は運行情報欄がないか系統が1つも読めない、シルバーフェリー・さんふらわあは運航情報の欄がない（さんふらわあは欄が空でも）、新日本海フェリーはヘッダーのお知らせ欄がない
- 空港の `flights[].kind`：`cancelled`（欠航）／`delayed`（遅れ）／`diverted`（引き返し等）／`done`（出発・到着済みで30分以上遅れた便）
- 高速道路の `roads[].items[]`：`kind`（`closed` など）・`label`（通行止 など）・`major`・`section`（区間）・`direction`・`reason`（作業・雪など）・`detail`
- 高速道路の路線の状態：通行止があれば `suspended`、重要な規制（ランプ閉鎖・チェーン規制・冬用タイヤ等装着・片側交互通行・渋滞・事故・故障車・落下物）があれば `delay`、それ以外は `normal`。車線規制・速度規制・除雪作業などは状態に使わず、ページでは件数だけ出す
- 中央バスの `groups[].items[]`：RSS の項目1つ（系統×方向、または便）。`id`（系統番号 rsn）・`route`（系統名）・`direction`（例「札幌→小樽」）・`time`（便ごとの運休の発車時刻。ないときは null）・`label`（状態の語）・`status`（運休中は `suspended`、一部区間・一部便・便ごとの運休は `delay`）・`url`（系統ごとの運休一覧）。区分の状態は、項目が1つでもあれば `delay`（RSS には運休のない系統が載らず、全系統の数が分からないため `suspended` にはしない）。状態の語が読めない項目があれば `source_warnings`
- 北都交通の `items[]`：`id`・`name`（都心線 など）・`about`（区間）・`status`（アイコン 01→`normal`、02→`delay`、03→`suspended`）・`label`（北都交通の表記のまま）・`url`
- シルバーフェリーの `sailings[]`（お知らせが出ているときだけ）：`date`・`from`（八戸／苫小牧）・`to`・`time`・`ship`（船名）・`status`（欠航・運休は `suspended`、遅れ見込みかお知らせを確認は `delay`、出港済・運航予定は `normal`）・`label`。`source_time` はお知らせの題名の「（3月15日16:00現在）」
- フェリーの状態：シルバーフェリーは `normal`／`delay`（欠航か遅延）。さんふらわあは通常運航 `normal`、欠航の語があれば `suspended`、遅れの語か知らない書き方なら `delay`。新日本海フェリーはお知らせがあれば `delay`
- 空港の系列の状態：欠航・引き返しが3割以上 → `suspended`、欠航・引き返しか30分以上の遅れが1便でもある → `delay`、それ以外 → `normal`。`done` の便は状態の判定に使わない

## 決めたこと

- **Cron を :02, :07, … にした**：新千歳空港の FIS は毎時 :01, :06, … に更新される。:00, :05, … に取ると、いつも約5分前のデータになっていた
- **次回の更新時刻は Worker が出す**（`next_update_at`）：Cron の設定をページ側に二重に持たないため
- **空港の遅れの判定は30分以上**：5分遅れ1便で系列全体が「遅れ」になるのは過敏だったため
- **出発・到着済みの遅れ便は30分以上だけ**：平常の日でも15分以上の遅れは60便近くある。ページでは初期は隠し、チェックボックスで表示
- **事業者の長文は取り込まない**：状態・便名・時刻などの事実だけを扱う（資料の第6章）
- **企業ロゴは使わない**：公認と誤解されるおそれと、各社の利用規約のため。代わりに会社の色を使う
- **高速道路は道央道（苫小牧〜新千歳空港〜札幌JCT）と札樽道だけ**：道央道は函館〜士別剣淵と長いので、区間名に苫小牧・千歳・恵庭・島松・北広島・輪厚・札幌南・大谷地・札幌JCT を含むものだけを載せる
- **高速道路のカードには「出発前に必ず公式を確認」を出す**：表示まで10〜15分遅れるうえ、このページだけを頼りにされるのがいちばんのリスクのため
- **会社の色**
  - JR北海道 `#59bb32`、札幌市交通局 `#005eaa`、北海道エアポート `#0e819f`、北海道中央バス `#d60000`、北都交通 `#00b555`、シルバーフェリー `#005d82`、さんふらわあ `#005396`、新日本海フェリー `#1a436d`（バス・フェリーは公式サイトの CSS で多く使われている色。新日本海フェリーは本文の文字色の次に多い紺）、地下鉄のラインカラーは各社公式サイトの CSS で確認した値
  - 航空会社の機体色は色見本（PANTONE・DIC）からの参考値と、指定した値。2色の会社は FDA（赤に左端4分の1が黄）・AIRDO（上下で水色と黄）・スカイマーク（紺に黄色の★）
- **Cron は通年5分ごと**：期間で間隔を変えると `next_update_at` の計算や設定が複雑になるため、単純さを優先した（KV 書き込みは1日288回で無料枠内）
- **異常は `/health` を Worker の外から定期的に見て知る**：Worker 自体や Cron が止まったときにも気づけるようにするため。見るのは Grok Bot の Routine（構成を増やさないため、専用の監視サービスは使わない）。秘密情報（Webhook URL など）も持たなくて済む
  - 503 にする条件：`updated_at` が17分以上古い（Cron が3回動いていない）／同じ事業者で3回続けて失敗／`source_warnings` がある
  - 1回だけの失敗は一時的なことが多いので、200 のまま `notes` に載せる
- **`/status.json` は自サイトからしか読めないようにする**：Origin（なければ Referer）が `https://realryo1.github.io` か localhost のときだけ返し、それ以外は 403。他サイトへの埋め込みや流用で、事業者の情報が広がっていくのを防ぐため。ヘッダーは偽れるので完全には防げないが、節度としての制限。`/health` は外部の監視から見るので制限しない
- **`/status.json` は日本国内からだけ読めるようにする**（2026-10-27）：Cloudflare が判定した国（`request.cf.country`）が JP のときだけ返す。国外と判定されたときは CORS ヘッダー付きの 403（`{"error":"region"}`）にし、ページが位置情報の許可を求めて、約10km単位（小数1桁）に丸めた現在地を `?lat=&lon=` で付けて取り直す。国内かどうかは、朝鮮半島・台湾・中国・ロシアにかからない大まかな矩形（`index.js` の `JAPAN`）で見る。自国の SIM でローミングしている来訪者を弾かないため。VPN や座標は偽れるので、これも節度としての制限。`/health` は国外の監視からも見るので制限しない。位置情報がすでに許可されていれば、ボタンを押さなくても確かめる
- **IP ごとのレート制限はゆるめ**（2026-10-27、10秒に60回。`wrangler.toml` の `[[ratelimits]]`）：携帯回線や会場の Wi-Fi は CGNAT で大勢が同じ IP を使うので、厳しくすると当日まとめて弾かれる。連打や機械的な取得だけを弾く。数え方は Cloudflare の拠点ごとの大まかなもの。Worker の中で弾いても Workers のリクエスト数（無料枠1日10万回）は減らず、減るのは KV の読み取りだけ。リクエスト数ごと止めるには、独自ドメインに載せて WAF のルールを使う必要がある（未対応）
- **KV の値は isolate のメモリに60秒持つ**（2026-10-27）：workers.dev では Cache API が効かないため（公式の説明では、効くのは独自ドメインのとき）。前はエッジのキャッシュ（`caches.default`）を使っていたが、実際には毎回 KV を読んでいたとみられる。`/health` も同じものを読む
- **リンクはページに直書きする**（2026-10-27、`delay.js` の `OFFICIAL`・`JR_SENKU`）：JSON の `url` は取得先の記録として Worker に残すが、ページでは使わない。事業者のページから毎回取ってくるリンク（中央バスの系統ごと・北都交通の系統ごと・シルバーフェリーのお知らせ・新日本海フェリーのお知らせ）だけ、決まった形（https・ホスト・パス。`delay.js` の `LINK`）に合うときに使い、合わなければ決まったページへ。事業者のページが改ざんされたときなどに `javascript:` のリンクが入らないようにするため
- **配信のキャッシュは短いまま**（`max-age=60, stale-while-revalidate=300`）：資料の案（`swr=86400`）だと古い運行情報が出続けるおそれがある。Worker や KV が止まっても、ページは前に表示した内容を残し、`updated_at` が古ければ「更新が止まっています」と出すので、長いキャッシュは使わない
- **バス2社は運休だけを出す**：どちらの会社も遅れの情報は出していない。運休の理由や詳しい案内は事業者の文章なので取り込まず、系統ごとのリンクで案内する
- **行き先ごとのまとめをページの先頭に出す**（資料の `status_summary` の代わり）：資料は全体で1つの状態を持つ案だったが、交通機関が多く1つにまとめると意味が薄いので、行き先ごとにした。集計はページ側（`delay.js` の `SUMMARY`）だけで行い、Worker の JSON は変えない
  - 行き先と手段：札幌⇄新千歳空港（JR 快速エアポート・中央バス 空港連絡バス・北都交通 空港連絡バス・道央道）、札幌⇄小樽（JR 函館線・高速おたる号・札樽道）、札幌市内（地下鉄3路線）、北海道⇄本州（新千歳空港の便・JR 特急と新幹線・フェリー3社）
  - 判定：手段どうしは代わりになるので、すべて平常／一部に乱れ（平常の手段あり）／すべての手段に乱れ（すべて運休・通行止なら、そう出す）の段階にする。サービス時間外と取得できない手段は判定に使わない。取得に失敗している事業者は、前回のデータで判定せず「取得できず」にする
  - 北都交通は都心線・大谷地線だけで見る（桑園線・定山渓線は通年「全便運休」のことがあり、入れると常に乱れに見えるため）

  - 手段を押すと、そのカードへ移る（カードに `id="dl-{id}"`、フェリーは `dl-ferry`）
